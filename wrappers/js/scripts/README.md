# JavaScript release scripts

## Bootstrap a new npm package for trusted publishing

[`publish-js.yml`](../../../.github/workflows/publish-js.yml) publishes through npm trusted
publishing (GitHub Actions OIDC), without a long-lived npm token. npm configures this trust
relationship separately for every package name, and the package must already exist in the registry
before its trusted publisher can be configured.

Use [`bootstrap-npm-trusted-publishing.sh`](bootstrap-npm-trusted-publishing.sh) once whenever the
release gains a new npm package name, such as a package for a new operating system, CPU, or libc.
This is not needed for ordinary version bumps.

Run this process **before creating the first release tag that references the new package**. Otherwise
the multi-package publish can stop halfway through and leave a partial release.

### 1. Register the package name

Add the exact scoped package name to the `PACKAGES` array in
`bootstrap-npm-trusted-publishing.sh`. It must match:

- the package name generated by `build-js-packages.yml`;
- the corresponding `optionalDependencies` entry in `wrappers/js/package.json`; and
- the name that `publish-js.yml` will publish.

Commit and review that change with the code that introduces the new platform package.

### 2. Log in to npm locally

Use an npm account with permission to publish public packages under the `@bloxbean` scope and with
account-level 2FA enabled:

```bash
npm login
npm whoami
```

Do not put an npm token in this repository or in the GitHub publish workflow. The local login is
used only to create the package name; subsequent real releases use OIDC.

### 3. Publish the bootstrap placeholder

From the repository root, run:

```bash
./wrappers/js/scripts/bootstrap-npm-trusted-publishing.sh
```

For each package in its list, the script first runs `npm view`. Existing package names are printed
and skipped. A missing name requires explicit confirmation before anything is published. Confirm
only the newly added package.

The script creates:

```text
<new-package-name>@0.0.0-oidc-bootstrap.0
```

This is a minimal public placeholder under the `preview` tag. It contains no native library and
must not be used as a real release. Publishing is irreversible: npm never permits reusing the same
package-name/version pair.

Verify that the package now exists:

```bash
npm view <new-package-name> name versions dist-tags --json
```

### 4. Configure the trusted publisher

On npmjs.com, open the new package and select **Settings → Trusted Publisher → GitHub Actions**.
Configure:

```text
Organization or user: bloxbean
Repository:           cardano-client-bindings
Workflow filename:    publish-js.yml
Environment:          release
Allowed action:       npm publish
```

The workflow filename is only the filename, not `.github/workflows/publish-js.yml`. The environment
must match the `environment: release` declaration in the publish job.

As a CLI alternative, install npm 11.15 or newer and run:

```bash
npm install -g npm@^11.15.0
npm trust github <new-package-name> \
  --repo bloxbean/mesmo \
  --file publish-js.yml \
  --environment release \
  --allow-publish
```

The CLI operation requires write access to the package and account-level 2FA. Confirm the resulting
configuration with:

```bash
npm trust list <new-package-name>
```

See npm's documentation for
[trusted publishers](https://docs.npmjs.com/trusted-publishers/) and
[`npm trust`](https://docs.npmjs.com/cli/v11/commands/npm-trust/).

### 5. Release through CI

Only create or approve the release after every package name exists and has the trusted publisher
configured. The real package version must be published by `publish-js.yml`, so it receives the
GitHub Actions provenance statement.

If a release already stopped after publishing some packages, do not blindly rerun it. npm will
reject every package-name/version pair that succeeded in the first attempt. Bootstrap and configure
the missing package first, then use an idempotent recovery workflow that skips versions already in
the registry.
